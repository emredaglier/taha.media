# 12. Public pages are static and revalidated by tag on publish; /isler renders per request

Date: 2026-11-05 · Status: accepted (rendering mechanism changed 2026-11-08)

`/isler/[slug]` is prerendered through `generateStaticParams`, which returns an empty list when there is no database. The Docker image builds with none, and a page must not read content at build time (`infra/README.md`, "What the frontend must provide", item 8), so Work pages render and cache on first request. `/`, `/hakkimda`, `/gizlilik` and `/galeri` are `force-dynamic` for the same reason, and their data comes from tag-cached Local API reads (this record first said they were prerendered). When content is published, `cms` tells `web` over the internal Docker network to revalidate the tags it touched: the Work, the Works list, Home when the Work is featured, a global's own tag, and the `gallery` tag when a Gallery item changes (Gallery items have no drafts, so every save counts). There is no time-based revalidation. `/isler` reads `?disiplin=`, so Next renders it per request. Its data still comes from tag-cached Local API reads, and HTML isn't edge-cached anyway (ADR-0004). A path segment such as `/isler/motion` was rejected because it would collide with Work slugs. The preview container (ADR-0001) renders drafts on every request.
